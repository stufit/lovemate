# 진행자용 — 첫 5쌍 관찰 절차

상태: 준비 자료. 실제 모집·관찰·구매는 미실행입니다. 표본은 시장 수요의 통계적 확증이 아닙니다.

## 준비

- 커플 코드 P01~P05를 먼저 정합니다. 중단하거나 어려움을 겪은 커플을 성공 사례로 교체하지 않습니다. 추가 관찰은 P06부터 별도 기록합니다.
- 두 사람 모두 성인이며 공개 범위를 이해하고 자발적으로 참여하는지 각자 확인합니다. 실제 이름·나이·연락처·원문 답변·대화 내용을 기록 파일에 쓰지 않습니다.
- 참여/비교/예정 가격/기기 복구 제한/삭제 범위를 [참가자 안내](participant-guide.md)로 설명합니다.
- 가격을 보여준 시점과 가이드를 무료로 체험한 시점을 구분합니다. 모의 결제 완료를 실제 구매로 기록하지 않습니다.
- 상대 응답을 미리 엿보거나 응답 선택에 관여하지 않도록 각자 답하는 시간을 줍니다.

## 접속 방식

2026-11-23 결정: **같은 자리에서 직접 관찰**. 아래 대면 절차를 사용한다. 진행자용 요약은 [대면 테스트 체크리스트](on-site-checklist.md)에 있다.

### 같은 컴퓨터에서 직접 관찰

1. `pnpm dev`를 실행하고 `http://127.0.0.1:3200`을 사용합니다.
2. A와 B는 **서로 다른 쿠키 저장소**를 사용합니다. 예: 별도 테스트용 Chrome 프로필 A + 시크릿 창 B, 또는 Chrome A + Firefox B.
3. 같은 Chrome의 시크릿 창 두 개는 쿠키를 공유할 수 있으므로 두 참여자의 분리 방법으로 쓰지 않습니다.
4. 기존 운영자 브라우저의 쿠키를 지우지 말고 테스트 전용 프로필을 사용합니다. 참가자가 바뀌면 이전 테스트 프로필을 종료하고 새로 준비합니다.
5. 같은 기기라도 서로의 응답 화면을 보지 않도록 진행하고, 초대 링크만 전달합니다.

현재 앱은 루프백 전용입니다. 다른 휴대전화·컴퓨터에 `127.0.0.1` 링크를 보내면 그 사람 자신의 기기를 가리키므로 접속할 수 없습니다.

### 원격 링크로 관찰

현재 지원 준비가 완료되지 않았습니다. 테스트용 배포 주소, 접근 범위, DB/백업/삭제·문의 담당, 테스트 안내를 먼저 정해야 합니다. 로컬 DB 포트 개방이나 개발 서버의 무단 외부 노출로 대신하지 않습니다. 실제 PG 없이 테스트하려면 상용 환경과 구분되는 별도 테스트 배포 모드를 설계해야 합니다. 현재 production의 mock 차단을 임의로 해제하지 않습니다.

## 과제와 관찰 항목

참가자에게 아래 **목표**를 주고, 버튼 위치나 정답을 먼저 설명하지 않습니다. 막힌 경우 무엇이 어려운지 묻고, 도움을 준 사실을 기록합니다. 무조건 끝내게 하지 않습니다.

| 단계 | 참가자에게 줄 목표 | 진행자가 볼 것 | 기록 |
|---|---|---|---|
| 랜딩 | 어떤 서비스인지 보고 시작해주세요 | 무료 범위·함께 참여·한계를 이해하는가 | LANDING |
| A 설문 | 평소 더 편한 쪽에 답해주세요 | 양끝/가운데 해석, 용어·뒤로가기·저장 이해 | QUESTION_WORDING / SAVE_RESTORE |
| 개인 결과·초대 | 상대와 함께 결과를 확인할 준비를 해주세요 | 초대 생성·복사·B 진입을 스스로 찾는가 | INVITE |
| B 설문 | 초대를 확인하고 자신의 답을 담아주세요 | 참가 동의·답변 공개 범위 이해 | INVITE / QUESTION_WORDING |
| 무료 결과 | 이 결과가 무슨 뜻인지 설명해주세요 | 상대 마음 판정/관계 등급으로 오해하지 않는가 | RESULT / WRONG_EXPLANATION |
| 첫 대화 | 편한 질문 하나를 골라 이야기해보세요 | 실제 대화 시작 여부, 건너뛰기 선택 | startedConversation |
| 가격 확인 | 이 시점에 추가 가이드가 필요할까요? | 무료 결과만 본 구매 의향과 이유 | premiumIntention |
| 선택 체험 | 원하면 가이드 하나로 대화를 이어가세요 | 예시·약속 양식의 구체적인 실용성 | GUIDE / describedSpecificValue |
| 마무리 | 이어서 접근하고 삭제하는 방법을 찾아보세요 | 재접근·삭제 범위 이해 | SAVE_RESTORE / DELETE |

‘모든 문항 답변’, ‘모의 결제’, ‘만족한다고 응답’을 유도하지 않습니다. 관찰 시간은 실제 측정하되, 전체 완료 시간을 제품 광고에 사용하기 전 별도 검토합니다.

## 인터뷰 질문

- 추가 설명 없이 이 결과의 의미를 자신의 말로 말해주세요. **도움을 준 뒤 이해한 경우 `understoodWithoutHelp=true`로 기록하지 않습니다.**
- 무료 질문이나 가이드로 실제 대화를 시작했나요? 버튼 클릭·리포트 열람만으로 사용으로 추정하지 않습니다.
- 어떤 구성 요소가 어떤 행동에 도움이 됐는지 설명할 수 있나요? ‘그냥 좋아요’만으로 구체적 가치 확인으로 기록하지 않습니다. 개인 대화 내용은 받지 않습니다.
- 답변이 가깝게 나온 경우에도 그에 맞는 질문을 실제로 살펴봤나요? 관찰한 경우에만 `similarAnswerCase=true`로 표시합니다. 답변값이나 차이 개수는 기록하지 않습니다.
- 예정 가격을 처음 봤을 때 왜 선택하거나 선택하지 않겠다고 생각했나요? 가이드를 체험한 뒤 의견과 혼합하지 않습니다.
- 하나만 바꾼다면 무엇을 바꾸고 싶나요? 사적인 설명 대신 UI·문항·가이드의 문제 코드로 기록합니다.

## 기록과 판단

[기록 양식](recording-guide.md)을 사용합니다. 데이터 파일은 Git에서 제외된 `.local-validation/`에 보관합니다. 단계만 수행하고 판정하지 못한 항목은 null로 둡니다.

첫 5쌍 중 4쌍 이상이 도움 없이 이해하고, 3쌍 이상이 실제 대화와 구체적 유용성을 함께 설명하며, 답변이 가까운 사례도 관찰해야 콘텐츠 다음 실험을 검토합니다. 이 기준을 통과해도 실결제·출시·사업성이 검증된 것은 아닙니다. 답변 노출이나 잘못된 결과 설명 문제는 먼저 수정합니다.
