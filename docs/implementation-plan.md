# MVP 구현 계획

작업 브랜치: `codex/woorisai-mvp` (기준: `develop`).

사용자가 v1.1 설계를 기준으로 개발을 요청했다. 이에 로컬 검증용 Phase 1~3을 구현하되, 실제 고객 검증을 통과한 것으로 간주하거나 실결제를 공개하지 않는다. DB는 기존 Docker `psql_ptk_17`의 1992 포트를 사용한다.

- [x] 공유 도메인: 12문항·입력 검증·비교·주제 선택·결정적 콘텐츠.
- [x] PostgreSQL migrations와 seed; 운영/통합 테스트 DB 분리.
- [x] NestJS API: 세션·쿠키·초대·임시저장·제출·결과·피드백·삭제.
- [x] 모의 결제: 주문·권한·보류·실패·취소·환불·중복 방지.
- [x] Next.js: 랜딩·샘플·설문·대기·무료 비교·대화 가이드·정책 초안.
- [x] 단위·DB 통합·모바일 2브라우저 E2E·프로덕션 빌드.
- [x] 실행 문서·운영 미확정 항목·Phase 0 관찰 양식.

실제 고객 인터뷰·PG 계약/실결제·법적 정책 확정·운영 배포는 미완료 상태로 유지한다.


## 검증 결과 (2026-11-20)

- `pnpm typecheck`: 통과.
- `pnpm test`: 7개 통과. 문항별 25개 조합, 세 샘플 fixture, 반대 응답/동일 평균, 모두 중립의 질문 중복·해석 확인.
- `pnpm test:integration`: 실제 PostgreSQL 전용 테스트 DB에서 7개 통과. 동시 참가, 제출/결과 멱등, 비공개 응답, 모의 거래 금액 검증, 공동 권한, 환불, 웹훅 재전송, 피드백, 삭제, 만료 확인.
- `pnpm test:e2e`: Google Chrome에서 3개 통과. 390px 독립 A/B 흐름, 새로고침 복구, 모의 성공/실패/보류/취소/환불, 두 사람 열람, 인쇄 CSS, 360/390/1440px 가로 넘침·페이지 오류 확인.
- `pnpm build`: Next.js 최적화 빌드 및 NestJS 번들 성공. 번들 실행 후 `/api/v1/health` 정상 응답 확인.
- 공개 요청 로그 비활성화, 개인 API no-store, `.env`와 빌드/테스트 산출물의 Git 제외 확인.
- 실제 고객 인터뷰·정식 출시 적합성·실결제·배포·자동 운영은 **미검증/미구현**. 자동 테스트는 사용 효과나 사업성을 입증하지 않는다.

## 실행

기존 PostgreSQL Docker 1992 포트를 사용한다. 로컬 `.env`는 준비되어 있으며 `pnpm dev`로 웹 `http://127.0.0.1:3200`과 API 4000을 실행한다. 새 checkout 설정은 README를 따른다.


## 후속 단계 — 첫 5쌍 검증 준비 (2026-11-20)

- 참가자 안내·진행자 과제·인터뷰·관찰 기록 사용법 작성.
- `validation:init` / `validation:report` 추가: 미관찰 null, 실제 대화+구체적 가치 교집합, 첫 5쌍 고정 집계.
- 가격 의향·모의 가이드 이용을 실제 구매와 분리. 익명 관찰 파일은 `.local-validation/`에 생성하며 Git에서 제외.
- 집계 규칙 테스트 5개 추가, 기존 포함 단위 테스트 12개 통과. 문서 링크·초기 0쌍 집계·Git 제외 확인.
- 기존 웹 3200 / API 4000 정상 응답 확인. 사용자 확인용 개발 서버는 유지.
- 실제 모집·연락·관찰·원격 배포는 미실행. 현재 실제 관찰 0쌍. 진행 방식 선택 후 해당 환경에서 수행.
